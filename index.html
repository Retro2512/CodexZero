02 / What the 79% means

Less setup on every request.

Codex sends its model instructions again whenever it makes a model request. Full lean replaces the dated 3,552-token instruction block with a 738-token version. The model, reasoning effort, your global instructions, and your project instructions stay the same.

The result is 2,814 fewer model-instruction tokens per request. Full lean is the install default. Command-output-only mode keeps the existing model prompt.

06 / FAQ

Where CodexZero fits.

These tools work at different layers, so their published percentages are not directly comparable.

How is this different from RTK?

RTK filters shell-command output with command-specific grouping, truncation, and deduplication. CodexZero works inside its Codex build, retains the raw result, and rejects any compact view that is not smaller. RTK covers more commands; CodexZero uses a narrower reversible-by-default contract.

How is this different from Headroom?

Headroom compresses a broader context surface through a library, proxy, or MCP server and can retrieve omitted content. CodexZero focuses on Codex tool results and exact local fallback. Headroom is broader; CodexZero has less routing and compression machinery.

What about Caveman and Ponytail?

Caveman asks the model to answer more briefly. Ponytail steers implementation choices toward less code. Both can complement tool-output reduction. CodexZero works on tool-result representation instead of adding those behavior instructions.

Does the 84.0% fixture result predict session savings?

No. It is the combined result of eleven fixed payloads, and almost all of the reduction came from two highly repetitive fixtures. Real savings depend on how often your tool results contain patterns the codec can shrink.

What changes in full-lean mode?

It replaces the model-instructions file for CodexZero launches. It removes repeated behavior scripting, permanent taste rules, response formatting rituals, fixed progress timing, and old model workarounds. Concise intermediary updates and the core authorization, preservation, verification, and reporting rules remain.

Do fewer input tokens mean lower cost or more requests?

They leave more room inside the input-token part of the workload. The dated prompt comparison gives 4.8× prompt capacity because 738 fits into 3,552 about 4.8 times. Total price and plan usage do not change by that exact ratio because output, other input, caching, and service rules also count.
